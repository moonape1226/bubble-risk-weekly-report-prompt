# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A twice-weekly (Mon + Thu, Asia/Taipei) market "bubble risk" report in Traditional Chinese. `bubble-risk-weekly-prompt.md` defines the methodology and runtime workflow; `report_contract.json` is the **canonical machine-readable contract** for locked headings/table headers, terminology-lock sections/synonyms, dimensions/weights, tiers, anchors/features, calibration, source IDs/order/classes/component windows/zero-result eligibility/aggregation, trigger reasons, and persisted states. This file only describes surrounding mechanics. Never hand-copy or independently redefine machine-enforced metadata in code or runtime instructions.

Production must load the prompt, contract, fetcher, and validator from one checked-out prompt-repo tree or one resolved immutable commit SHA. Never combine independent reads from moving `main`; inability to establish one revision is fail-closed.

This directory is a clone of the prompt repo `moonape1226/bubble-risk-weekly-report-prompt`. A Claude cloud routine fetches the prompt and executes it; reports are written to a **separate** archive repo `moonape1226/bubble-risk-archive` at runtime. No reports are stored here. (Editing the prompt locally and pushing to the prompt repo is ordinary git — the connector-only rule below applies only to how the routine archives reports.)

## Data sources & the network gotcha

- FRED API is primary (all macro series); fallbacks are US Treasury XML (rates) and EIA (`RWTC`, WTI). SEC EDGAR is used for insider Form 4 screens. Spot quotes come via WebFetch/WebSearch (not yfinance).
- Keys in `.env` (never printed): `FRED_API_KEY`, `EIA_API_KEY` (also read in `scripts/fetch_macro.py`).
- **WebFetch to FRED hosts is WAF-blocked (HTTP 403).** Workaround: fetch with Python `urllib` over Bash using a custom User-Agent `bubble-risk-weekly`. Many sources are tagged `[primary: SEARCH]` to dodge 403s.

`scripts/fetch_macro.py` (stdlib only) fetches the contract macro series plus `SP500` (200-DMA / 52-week deviation), computes deltas vs the prior-run date, and degrades per series (`ok` / `derived` / `fetch_failed`). Treasury fallback reads current/prior-year partitions; a failed current-year partition fails the series, while a prior-year failure can preserve the current level but omit its delta. Non-FRED blocks include `cftc_lev_funds`, `move_index`, `ofr_repo` (OFR STFM tri-party repo **transaction volume**), and derived `repo_stress` (SOFR−IORB / SOFR99−IORB plus `RPONTTLD` SRF usage/operation amount). `repo_stress.as_of` is the SOFR observation/reference date (normally published T+1), not the publication date. Preserve every usable `repo_stress` leg under partial availability. `no_new_obs: true` means a successful zero delta. CPI YoY requires the exact prior-year calendar month; a merely nearby 350–380 day observation is insufficient. Derived breakeven and repo legs carry bounded `alignment_observations` provenance so the validator can independently reproduce every selected leg. Decomposition movement and freshness are separate; baseline emits `status=baseline_no_prior`, `driver=baseline`, and `freshness=not_applicable`. Derived `vix_spx_comove` is **not** a prior-run delta: FRED publishes `SP500` a business day ahead of `VIXCLS`, so its window is a trailing pair taken from the dates the two series share inside their bounded `alignment_observations` proofs (`sp500_trend` carries one for this reason). No reproducible shared pair emits `status=unavailable` with `comove=false`; a verdict is never assembled across two windows. Usage: `python3 scripts/fetch_macro.py <prior-run-date|none>`.

The fetcher emits exactly one `===MACRO_JSON_START===` / `===MACRO_JSON_END===` envelope with `contract_version`, `macro_schema_version`, and `generated_at`. Save its complete marker-delimited output unchanged; never strip the markers, save only the bytes between them, reformat the JSON, or inject metadata. Invalid/mismatched metadata is fail-closed in production.

Evidence is source-keyed. Raw data uses exact header `| source_id | 指標 | 數值 | 來源（FRED series ID / URL） | 資料日期 | 抓取 timestamp |`; every successful API/DIRECT/derived Coverage row needs a Raw row with the same ID, and every SEARCH-VERIFIED row needs same-ID traceability. For macro `aggregation: all`, same-ID Raw rows cover every required component; `any` covers every component used as evidence and at least one successful component. Component identifiers match as exact tokens (`SOFR` does not match `SOFR99`), and each unambiguous macro Raw row must reproduce its value and date together from the artifact. Validate each 7d/14d/30d/90d claim against that source component's window, plus the calendar-quarter gate when `same_quarter: true` (analyst TP is `window: 90d` plus `same_quarter: true`). Hyperscaler financing mix and capital cycle each split into `quarterly_state` (`stock_of_state`) and `event_scan` (`30d`); global approvals use `7d`. Zero-result success is limited to the four contract-eligible screens (rename/SPAC, microcap, Form 4, US single-stock ETF). Optional technical failure is `⛔ FETCH FAILED`; a successfully completed optional screen with no disclosure is `✗ NOT DISCLOSED`; required unsatisfied aggregation is `⛔ FETCH FAILED`. Composite status follows contract `all`/`any`: Treasury basis trade is `any`; Fed funds, global central banks, and repo are `all`.

`scripts/validate_report.py` is the deterministic pre-archive gate. Every invocation includes the report, the standalone current score, prompt, contract, complete marker-delimited macro artifact, exactly one prior mode, and exactly one explicit run mode:

```sh
python3 scripts/validate_report.py <report.md> --current-score <current-score.json> --prompt bubble-risk-weekly-prompt.md --contract report_contract.json --macro-json <macro-output.txt> --prior-score <prior-score.json> --production
# or, only when there is no usable prior run:
python3 scripts/validate_report.py <report.md> --current-score <current-score.json> --prompt bubble-risk-weekly-prompt.md --contract report_contract.json --macro-json <macro-output.txt> --baseline --production
```

For dry-run, replace `--production` with `--dry-run`; production forbids the dry-run banner and dry-run requires it as the report's first line. `--prior-score` and `--baseline` are mutually exclusive, as are the two mode flags. The standalone current score must be semantically identical to the report JSON fence, and that same file is the only score payload that may later be archived.

Validation covers section-aware Markdown; source IDs/order/classes/windows/eligibility/aggregation and exact appendix headers; macro metadata and alignment provenance; score/state arithmetic and prior consistency; all-anchor feature audits; D5's contract-required IG OAS, Fed/ECB/BOJ balance-sheet, and PBoC disclosures; strict §3 values/freshness/directions plus CPI/T5YIFR chain markers and exact search-fallback markers; deterministic trigger reason codes and their evidence; mode banner; and persisted cross-run fields. Production is fail-closed on any missing artifact or non-zero result. Tests: `python3 -m unittest discover -s tests` (also run in CI).

## Methodology (locked)

Load dimensions, weights, tiers, anchors, feature rules/counts, calibration, reason-code severity, macro policies, and rounding behavior directly from `report_contract.json`; this file deliberately carries no second handwritten copy. Historical similarity must expose every feature audit line for every anchor, and summaries/§2 are recomputed from those lines. Qualitative hits and trigger reasons require successful in-window source evidence. Baseline makes every cross-period/delta/direction/streak trigger false; breakeven initial trigger requires breakeven driver **and** 10Y up **and** WTI up. D5 `扳機側` is only a summary of another independently validated reason and cannot upgrade the trigger state by itself.

## Report archival & git policy (cloud routine)

- Mandatory headings/tables/disclaimer and score schema come from `report_contract.json`; do not maintain a parallel count or literal inventory here.
- Archived date-keyed: `report-YYYY-MM-DD/{score.json, report.md}`. Production requires one branch-visible atomic commit containing both paths. This may be one native connector multi-file call or multiple connector Git Data preparation calls: create both blobs, one tree, one commit, then expose it with exactly one compare-and-swap `update_ref`. It does not need to be one tool call; two branch-visible per-file writes are forbidden. A same-day rerun atomically overwrites both files.
- Archive `score.json` from the exact standalone `--current-score` file that passed validation; do not regenerate it after validation.
- After the transaction lands on `main`, read both paths back and require exact content equality with the validated local payloads. A missing/mismatched readback is an archive failure; never claim success from the write response alone.
- The routine archives **only through GitHub connector mutation tools** (native multi-file or connector-exposed Git Data) to `main`. Forbidden inside the routine: local `git`/`gh` CLI, clone, curl/REST, GitPython. There is no `FORCE COMMIT` flag (overwrite is the default). `MODE: DRY-RUN` uses validator `--dry-run`, requires the banner, and skips every archive mutation.
